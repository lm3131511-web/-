# Prompt Versioning — Codex v2.2

## Политика версий
- Формат: `vMAJOR.MINOR.PATCH` (например, `v2.2.0` → `v2.2.1`).
- `PATCH`: правки текстов/инструкций без изменения схемы JSON и полей ответа.
- `MINOR`: добавлены поля/теги или изменены правила, но **обратная совместимость** сохранена.
- `MAJOR`: несовместимое изменение схемы ответа или контракта API.

## Golden sample
- Эталонный ответ хранится в конце файла `prompts/system_risk_v2.2.0.md` в «тестовом окне».
- При изменении логики/содержания промпта:
  1) обновить `prompt_version` (см. ниже),
  2) пересобрать эталонный пример,
  3) убедиться, что он проходит валидацию схемой.

## Изменение версии промпта
1. Обновить значение `prompt_version` в коде/шаблонах (файлы, где оно прокидывается в ответ).
2. Обновить «тестовое окно» (golden sample) в `system_risk_v2.2.0.md`.
3. Прогнать регрессию:
   - `pytest -q`
   - юниты по JSON-схеме (`tests/unit/test_llm_schema_validation.py`)
   - property-тесты (size caps)
   - интеграция для strict-JSON.
4. Задокументировать изменения в `docs/RUNBOOKS.md` (если влияет на операции).

## Связь с тестами
- Любое изменение промпта должно **не ломать**:
  - JSON Schema (`prompts/schemas/llm_risk_assessment.schema.json`),
  - инварианты `size_multiplier`,
  - обязательные теги/поля в ответе,
  - `short_reason ≤ 240` символов.
